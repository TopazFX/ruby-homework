# ExpenseTracker (Ruby)

Консольна програма для обліку витрат: додавання, перегляд, фільтрація, видалення,
статистика та імпорт з JSON-файлів. Дані зберігаються в локальному JSON-файлі.

**Автор:** Харина Сергій Сергійович, група КС31, ХНУ імені В. Н. Каразіна

## Вимоги

Ruby 3.0 або новіша (`ruby -v`). Зовнішні бібліотеки не потрібні.

## Запуск

```bash
ruby main.rb                 # дані в expenses.json поруч із main.rb
ruby main.rb my_data.json    # власний файл даних
```

> Windows (PowerShell): якщо кирилиця відображається некоректно, виконайте `chcp 65001`.

## Меню

| Пункт | Дія |
|-------|-----|
| 1 | Додати витрату (id генерується автоматично) |
| 2 | Переглянути всі витрати (за датою, потім за id) |
| 3 | Фільтр за категорією та/або періодом |
| 4 | Видалити за id із підтвердженням (y/n) |
| 5 | Статистика: загальна та сума за період |
| 6 | Імпорт з JSON-файла |
| 0 | Вихід |

Під час введення даних `:q` скасовує поточну дію. Суму вводять **цілим числом копійок**:
`12550` відображається як `125.50 грн`.

## Структура запису

| Поле | Вимоги |
|------|--------|
| `id` | унікальне додатне ціле |
| `date` | реальна дата `YYYY-MM-DD` |
| `amount_in_kopecks` | додатне ціле число копійок |
| `category` | `food`, `transport`, `study`, `entertainment`, `other` |
| `description` | непорожній текст до 200 символів (після видалення крайніх пробілів) |

## Збереження даних

- Файл відсутній: початок з порожнім списком.
- Файл містить `[]`: коректний порожній список.
- Файл порожній, пошкоджений або містить некоректні записи (чи повторювані id): програма
  виводить опис проблеми й завершується **без перезаписування файла**.
- Зміни записуються одразу після успішного додавання, видалення або імпорту (через тимчасовий
  файл). Якщо запис не вдався, стан у пам'яті **не змінюється**, а користувач бачить помилку.

## Імпорт

Приклад файла: `sample_import.json`.

- Імпорт працює за принципом «все або нічого»: якщо є некоректний запис, не імпортується жоден,
  а програма показує список проблем.
- Нові id призначаються після найбільшого наявного, тому конфліктів немає. Поле `id` у файлі
  імпорту необов'язкове (якщо воно є, воно перевіряється, але не використовується).

## Статистика

Загальна сума, суми за кожною категорією, найбільша витрата (якщо таких кілька, показуються всі)
та сума за період (обидві дати включно; початкова дата не може бути пізнішою за кінцеву).
